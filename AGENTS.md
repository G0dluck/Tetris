# AGENTS.md — Tetris

Справочный файл для ИИ-агентов и разработчиков, работающих с этим репозиторием:
архитектура, сборка, конвенции и «грабли» проекта. Прочитай его целиком перед
внесением изменений.

---

## 1. Обзор

Классический «Тетрис» на **C# / Windows Forms (.NET 8, net8.0-windows)**. Один проект,
одно окно, ноль внешних зависимостей (только системные сборки .NET). Комментарии
в коде местами на русском, строки UI и git-коммиты — вперемешку русский/английский.

Игра реализует: падающие фигуры (7 стандартных тетромино, рандомизация «7-bag»),
вращение с простым «wall kick», горизонтальное движение, ускоренное падение
(удержание ↓), твёрдый сброс (Space), пауза (P), предпросмотр следующей фигуры,
подсчёт очков, очистку линий, game over и сохранение рекорда.

**Git:** единственная ветка `master`, без CI, без тестов, без README.

## 2. Быстрый старт (сборка и запуск)

### Требования
- Windows (WinForms).
- .NET SDK 8.0+ (Visual Studio не обязательна — достаточно CLI).

### Сборка
```powershell
# из корня репозитория:
dotnet build Tetris.sln /p:Configuration=Debug
```

Результат: `Tetris\bin\Debug\net8.0-windows\Tetris.exe` (WinExe, запускается
напрямую; Windows Desktop Runtime 8.x ставится вместе с SDK).

### Запуск
- Открыть `Tetris.sln` в Visual Studio 2022 → F5, или
- запустить собранный `Tetris.exe` напрямую.

### Проверка после изменений
Всегда собирай проект после правок (`dotnet build Tetris.sln`)
и убедись, что нет ошибок компиляции. Юнит-тестов нет — проверяй поведение
вручную (контрольные сценарии: сброс линии, вращение у стен, game over).

## 4. Архитектура

### Разделение Game ↔ Form1
Класс `Game` (Tetris/Game.cs) не знает о WinForms-рендере. В конструктор он
получает **семь делегатов** для рисования/очистки клеток и рендера панелей:

```csharp
Game(int columns, int rows,
     Action<Point, Brush> drawGameCell, Action<Point> clearGameCell, Action renderGame,
     Action<Point, Brush> drawNextCell, Action<Point> clearNextCell, Action renderNext,
     Action clearNextBoard)
```

Результаты наружу — через события: `ScoreChanged`, `GameOver`.

### Ключевые классы

| Класс | Ответственность |
|---|---|
| `Program` | Точка входа, запуск Form1 |
| `Form1` | UI: панель поля (10×20), панель «Next», кнопка Start, счёт; ввод с клавиатуры; двойная буферизация на `BufferedGraphics` |
| `Game` | Доска `Cell[,]`, таймер падения, перемещение/вращение/блокировка, очистка линий, очки, «7-bag», твёрдый сброс/пауза, гейм-овер, рекорд |
| `Tetromino` | Фигура: `Position`, `CurrentState`, массив предвычисленных состояний вращения `Point[][]`, кисть цвета; статические фабрики `CreateI/O/T/J/L/S/Z` + `Create(int shape, ...)` (индекс фигуры из «7-bag») |
| `Cell` | `struct { bool IsOccupied; Brush Brush; }` |
| `ScoreEventArgs` / `GameOverEventArgs` | Данные событий |

### Доска и фигуры
- Поле: 10 колонок × 20 рядов (`const int Columns = 10; Rows = 20` в Form1.cs).
  Размеры клетки вычисляются делением размера панели: 201/10 ≈ 20px.
- Индексация доски: `board[row, column]` = `board[Y, X]` (Y — строка, X — столбец).
  Точка `(X, Y)`; фигура спавнится при `Y = 0`, X — случайный в пределах доски.
- 7 фигур, цвета через статические кисти:
  I→`Green`, O→`DarkRed`, T→`DarkViolet`, J→`YellowGreen`, L→`Blue`,
  S→`Orange`, Z→`Coral` (см. фабрики в Tetromino.cs).
- Вращение — переключение предвычисленных состояний (НЕ матричное вращение).
  У I — 2 состояния, у O — 1 (не вращается), у T/J/L/S/Z — 4.
- Рандомизация — «7-bag»: `NextShapeIndex`/`RefillBag` в Game.cs перемешивают все
  7 фигур (перемешивание Фишера–Йетса), каждая фигура выпадает ровно один раз за
  «мешок». Текущая и «next» создаются с шириной доски `columns` (позиция X —
  случайная в пределах поля), предпросмотр центрируется в панели 4×4.

### Игровой цикл (Game.cs)
1. `Timer` (WinForms, интервал 500 мс) тикает на UI-потоке → `TimerTick`.
2. Каждый тик: попытка сдвинуть фигуру вниз (`Y+1`). Если `CanPlace` — сдвиг,
   иначе: `LockTetromino` → `ClearLines` → `StartNewTetromino`.
3. Очки: +10 за блокировку фигуры (`LockTetromino`), +100 за каждую очищенную
   линию (`ClearLines`; при N линиях за тик — 100×N одним событием).
   Уровней/ускорения нет.
4. Падение с ускорением: `FastDrop(true)` (удержание ↓) меняет интервал на 50 мс.
5. Твёрдый сброс: `HardDrop()` (Space) мгновенно роняет фигуру на дно, затем —
   `LockTetromino` → `ClearLines` → `StartNewTetromino` (как обычный тик, но сразу).
6. Game over: новая фигура спавнится в занятые клетки → `OnGameOver`:
   таймер стоп, сравнение/сохранение рекорда в `Properties.Settings.Default.HighScore`,
   событие `GameOver`.

### Вращение и wall kick (Game.Rotate)
- Пробуем повернуть на месте; при коллизии — сдвиг влево/вправо на 1…2 клетки,
  затем — вертикальный сдвиг вверх на 1 клетку (для вращения у пола).
  Полноценной таблицы kicks (SRS) нет — «простой wall kick».

### Ввод (Form1)
- `←`/`→` — `game.Move(±1)`; `↑` — `game.Rotate()`; `↓` (down/up) — `FastDrop`;
  `Space` — `game.HardDrop()`; `P` — `game.TogglePause()` (на паузе ввод движения
  блокируется; состояние показывается в заголовке окна).
- При потере фокуса окна `Deactivate` сбрасывает `FastDrop(false)` (KeyUp может
  не дойти при зажатой ↓).
- `KeyPreview = true` на форме. Кнопка Start создаёт новый `Game` (старый
  останавливается и диспозится), дизейблится до game over.

### Рендер (Form1)
- Двойная буферизация: `BufferedGraphicsContext` + `panel.CreateGraphics()` на
  каждую панель (поле и «Next»). Буферы пересоздаются при изменении размеров
  панелей (`EnsureGameBuffer`/`EnsureNextBuffer`), окно — `FormBorderStyle.FixedSingle`.
  Сетка рисуется `DrawGrid`, клетка — `FillRectangle` с отступом 2px.
- Отрисовку полностью держит `Game` через делегаты; `Form1` лишь подменяет кисти
  и вызывает `Render()`. После пересоздания буфера `game.RenderBoard()`
  восстанавливает доску и текущую фигуру.

## 5. Конвенции кода

- Пространство имён — `Tetris`; отступы — 4 пробела; компилятор C# 12 (из SDK 8),
  существующий код написан в стиле C# 6/7 (`?.`, `nameof`, `?? throw`) — не
  переписывай его на новейший синтаксис без запроса.
- Фигурные скобки (Allman, `{` на новой строке) — обязательны у всех управляющих
  конструкций: `if`/`else`/`for`/`foreach`/`while`, включая однострочные тела.
  `switch`-кейсы — без скобок (стандарт C#).
- Именование: PascalCase — публичные методы/свойства/классы, camelCase — поля.
- Комментарии — на русском (существующие в Program.cs, Form1.Designer.cs);
  **не переводи массово** существующий код на другой язык.
- Строки UI — на английском («Start», «Score:», «Next:», «Game Over!»...).
- Паттерн интеграции UI↔логика — делегаты/события; новые возможности рендера
  добавляй тем же способом (делегат в конструктор `Game`), а не прямыми
  обращениями `Game` к контролам.
- `Game` реализует `IDisposable` (таймер); составляющие ресурсы освобождаются
  в `Form1FormClosed`.
- `Form1.Designer.cs` генерируется конструктором форм — ручные правки только по
  необходимости и аккуратно, в стиле существующего кода.

## 6. Известные проблемы и «грабли» (проверь перед изменением)

1. **Вращение без полноценной таблицы kicks (SRS)** — у стен вращение I/J/L
   может не работать так, как в классическом Тетрисе. Есть только
   горизонтальный kick на 1…2 клетки и вертикальный вверх на 1.
2. **Нет уровней/тени/холда/звука** — точки расширения: `Game` (логика)
   и `Form1.KeyDown` (ввод). Space и P уже заняты (твёрдый сброс/пауза) —
   новые клавиши выбирай из свободных.
3. **Буферы рендера (`Form1`)** — пересоздаются при изменении размеров панелей
   (`EnsureGameBuffer`/`EnsureNextBuffer`); окно — `FixedSingle`. Если вернёшь
   растягиваемое окно/DPI-скейлинг, проверь пересчёт `cellWidth/cellHeight`
   и пересоздание буферов + `game.RenderBoard()`.
4. **Таймер и пауза** — `TogglePause` останавливает/запускает `timer`;
   `FastDrop` меняет `timer.Interval`, и после паузы интервал не сбрасывается:
   при зажатой ↓ падение останется ускоренным (KeyUp/Deactivate снимет).
5. **Рекорд хранится в пользовательских настройках** (`App.config`, userSettings;
   физически — в `%LocalAppData%\Tetris\...\user.config`). Файл `HighScore` в
   App.config — лишь значение по умолчанию.
6. **Очки: +10 за блокировку и +100 за линию (при N линиях за тик — 100×N)** —
   без комбо.
7. Сборка возможна только на Windows (WinForms). Проект SDK-style
   (net8.0-windows) — `dotnet build` собирает его напрямую; прежняя ошибка
   MSB4216 относилась к старому csproj .NET Framework 4.5 и осталась в git-истории.

| Очистка линий (баги, анимация) | `Game.ClearLines`, `CopyRow`, `ClearRow`, `RedrawBoard` |

| Раскладка окна | `Form1.Designer.cs` (аккуратно) + пересчёт `cellWidth/cellHeight` |
| Рандом фигур / «7-bag» (реализован) | `Game.cs` — `NextShapeIndex`/`RefillBag`; `Tetromino.Create(index, random, columns)` |

## 8. Правила для агента

- Сначала прочитай `Game.cs`, `Tetromino.cs`, `Form1.cs` — это 90% логики.
- После любых правок — сборка через `dotnet build Tetris.sln` (см. §2) без ошибок.
- Не редактируй вручную то, что генерирует дизайнер (`Form1.Designer.cs`),
  без крайней необходимости.
- Соблюдай разделение Game↔UI (делегаты/события) — не тяни контролы в `Game`.
- Не удаляй и не переводи существующие русские комментарии без запроса.
- Стиль: фигурные скобки у всех `if`/`else`/`for`/`foreach`/`while` (см. §5).
- Тестов нет: после изменения игровой логики прогони вручную минимум:
  движение/вращение у стен, очистка линии (в т.ч. 2+ за тик), твёрдый сброс,
  пауза, game over и сброс новой игры.
